# PostCompact session-state logging plan

Status: implementation prepared for review; manual Claude /compact smoke check remains user-run.
Date: 2026-10-31

## Outcome

After each successfully handled PostCompact invocation, append one compaction event to `logs/session-state/<session_id>.jsonl`, using the session ID supplied by Claude and the timestamp generated by the existing SessionStateStore. Return no context or user-facing output on success.

This increment adds event recording only. No query helpers, enrichment decisions, counters, model calls, or session reset behavior.

## Verified hook and existing structure

Use the exact Claude event name `PostCompact` in plugin configuration and the dispatcher registry. The official hook reference says this event runs after compaction completes and supports manual and automatic triggers. `PreCompact` occurs before compaction and must not produce a completed-compaction record.

Source: https://code.claude.com/docs/en/hooks#postcompact (checked 2026-10-31).

Current main was inspected for:

- `plugins/hook-laya/hooks/hooks.json`: UserPromptSubmit invokes the common CLI hook command.
- `src/laya_context_router/hooks/gateway.py`: argument parsing, bounded input, deadlines, response serialization and diagnostic logging.
- `src/laya_context_router/hooks/dispatcher.py`: event validation and event-to-dispatcher registry.
- Merged PR #31: standalone TypeScript SessionStateStore, with save/load and strict append-only JSONL behavior.

The Python runtime cannot import the TypeScript class directly. A small adapter is required; duplicating the JSONL writer in Python would defeat reuse.

## 1. Register the plugin entry

Add this sibling to UserPromptSubmit in `plugins/hook-laya/hooks/hooks.json`:

```json
"PostCompact": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "\"${LAYA_CONTEXT_ROUTER_CLI}\" hook --hook PostCompact --log-state",
        "timeout": 15
      }
    ]
  }
]
```

Omitting the matcher covers both manual and automatic compaction. Keep registration in the plugin rather than duplicating it in settings.json. Users configuring a hook directly in settings.json use the same `PostCompact` key.

The executable and `hook --hook` entry point are reused. `--log-state` explicitly selects this invocation's state-logging action. No `--real` is needed because this path does not run LAYA. No repository-root argument is needed to record session metadata.

## 2. Route through the existing gateway and dispatcher

Add `--log-state` to the gateway's mutually exclusive invocation modes alongside `--real` and `--observe-only`. Validate that this initial logging mode is used with PostCompact; reject accidental use with another event. Preserve existing UserPromptSubmit behavior.

Register `PostCompact` in the common dispatcher and add:

- `src/laya_context_router/hooks/post_compact/__init__.py`
- `src/laya_context_router/hooks/post_compact/dispatcher.py`

Proposed function: `dispatch_post_compact(envelope, args, logger)`.

Use Python's existing snake_case folder convention, exactly as `user_prompt_submit` does for UserPromptSubmit. The external event name always remains `PostCompact`.

Processing sequence:

1. Gateway reads the hook payload and validates its event against `--hook`.
2. Common dispatcher validates common fields and routes PostCompact.
3. PostCompact dispatcher sees `args.log_state` and validates `trigger` as manual or auto.
4. It constructs the event below and passes it, with `envelope.common['session_id']`, to the adapter.
5. Await persistence, then return the existing `Noop` result with a specific success reason such as `session_state_logged`. Its serialization is empty stdout.

Without `--log-state`, PostCompact currently returns an unsupported-action no-op. This leaves its dispatcher available for additional actions later. A future PreCompact action gets a separate event registration and dispatcher.

Logging must not require project discovery, a valid source-code repository, model configuration or the enrichment flow. Use the existing identity enricher on this route; keep project enrichment on the existing route. Update gateway diagnostic mode/routing metadata for the new event.

## 3. Event naming convention and record shape

Hook records use the exact Claude hook name, including casing, for both `source.name` and `type`. Therefore PostCompact records have `type: "PostCompact"`; UserPromptSubmit records use `type: "UserPromptSubmit"`. Do not convert hook names to snake_case or substitute semantic aliases such as `compaction_completed`.

Flow records use `source.kind: "flow"`, the stable flow identifier in `source.name`, and snake_case action names in `type`, such as `context_enriched`. JSON property names retain the existing store contract. No SessionStateStore schema change is required: its type field already accepts these strings. During implementation, update the repository's session-state design/usage examples to state this convention; preserve existing historical JSONL records.


```json
{"source":{"kind":"hook","name":"PostCompact"},"type":"PostCompact","payload":{},"timestamp":"2026-10-31T19:00:00.000Z"}
```

Call `save` with source/type/payload only; the store supplies timestamp. The containing filename identifies the session. No duplicate session field is required in each line. The timestamp is logging time, not a timestamp measured inside Claude's compaction operation.

Do not save compact_summary, transcript content, or the entire incoming payload into the session log. Multiple completed compactions in one session append multiple records. Never clear the history. One invocation produces one append; repeated external delivery can produce duplicate records because this minimal schema has no reliable upstream event ID.

## 4. Reuse the store through a small adapter

Proposed additions:

- `src/laya_context_router/hooks/session_state.py`: Python adapter callable by the dispatcher.
- `typescript-helper/src/session-state-cli.ts`: standalone Node entry importing `./session-state` only.

The adapter passes a JSON request on stdin containing `logsRoot`, `sessionId`, and the event. Node constructs SessionStateStore, awaits save, and exits successfully only when saving completes. It prints no success text. Errors go to stderr with a nonzero child exit status. Use subprocess argument arrays, never shell interpolation. Reuse existing process-lifecycle utilities if compatible; inspect them before implementation.

Resolve logsRoot from the LCR installation root, following the existing diagnostic logger's root convention, not Claude's project directory or the current working directory. The resulting location is `<LCR-root>/logs/session-state/<sessionId>.jsonl`. Resolve the compiled Node entry relative to that same installation. Document the existing TypeScript build prerequisite; never install dependencies or compile inside a hook.

The bridge must propagate the gateway's remaining deadline, terminate and reap the child on timeout/interruption, and never retry an ambiguous append automatically.

Since each hook starts a process and the store queues only within one instance, serialize adapter writes per session. For the current Mac/POSIX runtime, use a small advisory file lock in `logs/session-state-locks/<sessionId>.lock`, held for the complete Node operation. Validate the session ID before constructing the lock path. Acquire with bounded polling against the remaining deadline; release in finally. Keep the lock file instead of deleting it, avoiding inode races. Different sessions can proceed independently. Future Python hook writers must reuse this adapter; direct concurrent Node writers remain outside this guarantee. This is coordination only, not a second persistence implementation.

## 5. Input size and failure behavior

The current gateway caps input at 65,536 characters, while PostCompact includes a summary of variable size. Make the cap event-specific: retain the existing limit for current events and use a documented 1 MiB character cap for PostCompact. Read only cap+1 and reject oversized input explicitly. Do not silently drop the summary before validating JSON. The summary is accepted as input but is not stored in the session record.

For this logging route, diagnostic records should contain metadata and input length rather than copy the summary through the gateway's existing raw-input/raw-payload logging. Ensure the common dispatch diagnostic also does not dump the raw payload.

Reuse the gateway's fail-open policy: failures become a Failure result and a clear stderr/diagnostic error, with no context response. Never report a successful append if Node failed. Missing Node/build, invalid IDs, malformed history, permissions, disk errors, oversized input and timeouts must all be distinguishable in diagnostics. Thus recording is best-effort under operational failures; the design does not promise every compaction can be persisted despite disk or timeout failure.

## 6. Small implementation steps and tests

1. Add the mode and routing contract, plugin entry, PostCompact dispatcher, and unit tests with a fake adapter.
2. Add the standalone Node entry and Python adapter with deadline/locking tests; reuse the existing store tests.
3. Connect the real adapter; add temporary-directory integration tests and usage documentation.

Required cases:

- Plugin JSON retains UserPromptSubmit and adds exactly one PostCompact logging entry covering both triggers.
- Correct event/flag routing; mismatched event, conflicting modes and unsupported actions do not write.
- Manual and automatic payloads create the same compaction event shape, with source.kind hook, source.name PostCompact, type exactly PostCompact, and empty payload. Assert that no compaction_completed alias is emitted.
- Missing/invalid session ID or common fields fails without creating a log.
- Missing/invalid trigger fails; unused extra fields are tolerated.
- Summary text, quotes, Unicode and large-but-supported summaries do not appear in session or route diagnostic logs.
- Oversized input fails explicitly; UserPromptSubmit input limits stay unchanged.
- Python-to-Node integration creates the correct session file with a valid timestamp and empty payload.
- Two sequential compactions append two lines; another session writes its own file; previous enrichment records remain intact.
- Existing corrupted logs, missing executable/build, filesystem failure and child nonzero exit surface as errors without false success.
- Concurrent adapter invocations for one session preserve all complete records; separate sessions are independent.
- Lock timeout, process timeout and interruption release resources and reap the child; no automatic retry.
- Success emits empty stdout and invokes no LAYA, tokenizer or extraction code.
- Existing gateway and UserPromptSubmit regression tests continue to pass.

Run the relevant Python hook tests, TypeScript build and tests, plus the new Python/Node integration tests. All automated cases use synthetic payloads and temporary files. A final user-run smoke check invokes manual /compact on a Claude version supporting PostCompact and verifies one new record under that session ID. Record the tested Claude version; do not silently substitute PreCompact on older versions.

The plugin routes PostCompact through the common dispatcher to its own dispatcher, which uses the merged store to append the minimal completion record. The plan adds no compaction query API. Implement only this integration and its focused tests in a later PR; experiments and model execution are outside scope.
